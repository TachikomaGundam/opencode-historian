# 写作风格与信息密度

> 控制 wiki 页面的信息密度、语言规范、双语写作惯例。

## 信息密度规则

| 规则 | 阈值 | 违反时的修正 |
|------|------|-------------|
| 导言占比 | 全文 10-15% | 超过则裁剪到核心结论；不足则补充概括 |
| 中文句长 | ≤20 字 | 拆为两句或用逗号分隔 |
| 英文句长 | ≤25 词 | 拆为两句或改为列表 |
| 结构化入表 | ≥3 字段 | 用表格呈现；≤2 字段用描述列表 |
| 来源列 | 对比表/时间线必含 | 补充来源列 |
| 无溢美词 | 零容忍 | 删除修饰词，用数据替代 |
| 无杂项筐 | 禁止「其他」「Miscellaneous」 | 归入具体主题或移出本页 |
| 固定尾部 | `## Related Pages` 必须存在且含真实链接 | 补链接或删除空节 |

## 双语写作惯例

wiki 页面是 **en/zh 孪生体**：同一路径、两种语言、节对节镜像。

### 标题

每种语言用自然标题：

| en | zh |
|----|----|
| Architecture | 建筑 |
| Incident Postmortem | 事件复盘 |
| KV Cache Tuning | KV 缓存调优 |
| Model Comparison | 模型对比 |

不混合语言。英文标题不出现在中文页，反之亦然。

### 正文结构

- **节序一致**：en 页的 `## Background` 对应 zh 页的 `## 背景`，顺序相同
- **表格结构一致**：列数和含义一致，列标题各用本语言
- **代码块不翻译**：命令、配置、代码保持原样
- **链接路径不翻译**：`[标签](/path)` 中 path 不变，label 翻译

### 状态块双语

英文页：
```markdown
> **Status**: Active | **Updated**: 2026-09-01 | **Scope**: How KV cache sizing affects throughput
```

中文页：
```markdown
> **状态**: 活跃 | **更新**: 2026-09-01 | **范围**: KV 缓存大小如何影响吞吐量
```

### 翻译行为

- `historian_page_create(twin:true)` 自动创建另一语言的孪生页
- `historian_translate_snippet` 手动翻译片段
- 代码块、表格行、URL 在翻译时被保护（不替换）
- 翻译失败时 en 页正常落库，zh 状态标 `pending`

## 中文写作细则

1. **用简体字**，不用繁体
2. **数字与单位**：数字用阿拉伯数字（`3 个`，不 `三个`），单位用国际符号（`ms`、`GB`、`tok/s`）
3. **中英混排**：中文与英文/数字之间加半角空格（`使用 Docker 部署`）
4. **标点**：中文语境用全角标点；引号用「」（不 ""）
5. **术语**：首次出现给中英对照（`KV 缓存 (KV Cache)`），后续用中文

## 禁止词汇

| 英文 | 中文等价 | 替代 |
|------|---------|------|
| robust | 强大的 | 用具体指标 |
| leverage / utilize | 利用 / 赋能 | 用「使用」 |
| streamline | 优化 | 写具体改了什么 |
| world-class | 领先的 | 给排名或基准 |
| cutting-edge | 先进的 | 给版本号 |
| in order to | — | 用「to」 |
| please don't hesitate | — | 删除 |
| delve | 深入 | 用「分析」或「调查」 |
